# 14. 설정 페이지

`docs/index.html` 하나짜리 자립형 페이지다. GitHub Pages 가 저장소 루트의 `docs/` 를
서빙한다.

**<https://chcbaram.github.io/NU87-TinyDK/>**

> 저장소 루트의 `docs/` 는 Pages 용이고, 펌웨어 문서는 여기 `firmware/docs/` 다.

## 14.1 전용 프로토콜을 만들지 않았다

페이지가 하는 일은 **CLI 를 그대로 몰고 그 출력을 파싱하는 것**뿐이다.

```js
const net = parseKV(await send('net info'));   // "key : value" 를 읽는다
```

펌웨어에 기계용 프로토콜을 따로 두는 안도 검토했지만, CLI 가 이미 모든 것을 할 수 있어서
명령을 두 벌 관리하게 될 뿐이다. 펌웨어에 명령이 늘면 페이지는 손대지 않아도 콘솔에서
바로 쓸 수 있다.

대가는 출력이 사람이 읽는 형식이라 파싱이 필요하다는 것이다. `key   : value` 꼴이 일정해서
정규식 한 줄이면 된다.

## 14.2 통로 추상화

펌웨어가 `uart_driver_t` 로 하는 것을 페이지 안에서도 한다.

```js
transport = { name, dataChannel, writeCli, writeDat, onDat, close }
```

그 위 코드는 통로를 모른다. 붙고 나면 화면도 완전히 같으므로 연결 수단은 탭이 아니라
헤더에 둔다 — 탭으로 나누면 같은 UI 를 두 벌 만들게 된다.

| | CLI | 대량 전송 |
|---|---|---|
| BLE | 0xFF88 / 0xFF89 | 0xFF8A / 0xFF8B (`ota write ... 4`) |
| USB | 같은 포트 | 같은 포트 (채널 인자 없음) |

**Web Bluetooth 는 Chrome / Edge 만 지원한다.** Safari 와 Firefox 는 안 되고 iOS 도 안
된다. Web Serial 은 데스크톱만이라 안드로이드에서는 USB 버튼을 숨긴다.

### CLI TX 를 반드시 구독해야 한다

`cli_mgr` 이 `cliBleIsConnected()` 로 CLI 를 BLE 로 넘길지 판단하는데 그것이 **notify
활성화 여부**를 본다. 데이터 채널만 구독하면 명령이 BLE 로 들어가도 CLI 는 USB 에 머물러
아무 반응이 없다.

## 14.3 화면 규칙 셋

쌓아 올리다 서로 어긋나기 시작해서 규칙을 셋으로 줄였다.

**면은 두 단계** — 바탕(`--bg`) > 카드(`--panel`) > 그 위 컨트롤(`--bg`). 예외 없음.
한때 콘솔만 반대(흰 바탕에 회색 상자)여서 위아래가 뒤집혀 보였다.

**패널 머리는 하나** — 왼쪽은 탭, 오른쪽은 그 패널의 동작. 위(보드/WiFi/펌웨어 + 갱신)와
아래(콘솔 + 접기/지우기)가 같은 틀을 쓴다.

**연결 상태는 컨트롤 자체가 바뀐다** — 버튼 색으로 나타내지 않는다. BLE 만 강조색이던 때는
연결 여부와 무관하게 "BLE 로 붙어 있다"로 읽혔다.

```
연결 전 :  NU87-TinyDK 개발보드        [BLE 연결] [USB 연결]
           연결되지 않았다

연결 후 :  NU87-TinyDK 개발보드           ● BLE  [해제]
           NU87-TINYDK · V260809R1 · ONLINE 172.30.1.97 · OTA2
```

### 높이는 한 축으로만 정한다

바깥(footer 높이)을 정하고 안에서 다시 flex 로 나누면 둘이 물려 계속 어긋난다. 출력창이
한 줄로 눌리거나, 끌면 화면 밖으로 넘어갔다.

정하는 값은 `#term` 높이 하나뿐이고 나머지는 따라온다. 드래그도 시작점 대비 이동량으로
계산한다 — 절대 좌표로 하면 여백을 하나라도 빠뜨렸을 때 커서와 경계가 어긋난다.

## 14.4 실측으로 잡은 것들

**notify 경계에 걸친 한글이 깨진다.** BLE notify 는 20바이트씩 잘려 오는데 한글은 UTF-8 로
3바이트라 글자 하나가 두 패킷에 걸치는 일이 흔하다. 패킷마다 따로 디코딩하면 양쪽 다
깨진다 — `"동기됨"` 이 `"동???됨"` 이 됐다.

```js
dec.decode(value, { stream: true })   // 걸친 조각을 다음 호출까지 들고 있는다
```

보내는 쪽은 문제가 없다. 펌웨어가 바이트를 그대로 모아 CLI 에 넘기므로 경계가 어디든 결과가
같다.

**USB 는 명령 에코가 응답과 같은 곳으로 돌아온다.** 첫 줄을 곧바로 응답으로 받으면 에코된
명령을 응답으로 착각한다. 기대하는 말이 나올 때까지 건너뛴다.

**탭 핸들러를 `.tabs button` 전체에 걸면 안 된다.** 콘솔의 탭에는 `data-tab` 이 없어
예외가 나는데, 그 전에 이미 모든 `.on` 을 지운 뒤라 본문이 통째로 사라진다.

**콘솔 높이 상한은 화면 기준이어야 한다.** 앱의 측정 높이를 기준으로 삼으면, 한 번 넘친
순간 그 값도 같이 커져서 끌수록 계속 커지는 되먹임이 생긴다.

## 14.5 로컬에서 열기

`localhost` 는 보안 컨텍스트로 취급되므로 Web Bluetooth 가 그대로 동작한다.

```
python3 -m http.server 8000 --bind 127.0.0.1 --directory docs
```

VSCode 태스크는 `util - pages` 다.
